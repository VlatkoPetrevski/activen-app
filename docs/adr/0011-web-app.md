# ADR-0011: Web апликација — Vite + React SPA (PWA), демо режим, заеднички договор

- Статус: Прифатено
- Датум: 2026-11-19
- Го заменува изборот „Next.js“ од ADR-0001 за web клиентот

## Контекст

ADR-0001 предвиде Next.js. При изработката на инкремент 3 (прва целосна верзија) ги разгледавме барањата:

- целата апликација е зад најава — нема потреба од SEO ниту server-side рендерирање на лични податоци;
- PWA: работа на телефон, инсталирање, брзо вчитување;
- истиот API го користат web и (подоцна) мобилната апликација — договорот (типови, правила) треба да е заеднички;
- корисникот (продукт сопственик) сака **прва верзија што може да се кликне и коментира** уште пред поврзување со уреди.

## Одлука

1. **Vite + React 19 + React Router 8 + TanStack Query** како SPA (PWA со `vite-plugin-pwa`). Статички фајлови
   (CDN), без Node сервер за web. Next.js нема да додаде вредност за апликација зад најава, а носи посложен deploy.
   Ако подоцна треба јавен маркетинг сајт, тој е посебен (статички) проект.
2. **`@activen/contracts`** — заеднички договор меѓу API и клиентите:
   - типови на одговорите (DTO), константи, **чисти „view builders“** (календар со план ↔ активност врски,
     напредок, редица за тренер со сигнали) — серверот и демото пресметуваат _исто_;
   - zod шеми за барања се посебна влезна точка `@activen/contracts/requests` (само сервер) — zod не оди во
     пребарувачот.
3. **Два режима на апликацијата** преку еден `Api` интерфејс:
   - `HttpApi` — вистинскиот API; access token само во меморија, refresh преку HttpOnly колаче, едно заедничко
     освежување при 401 (ADR-0010);
   - `DemoApi` — примерни податоци во меморија (8 недели маратонски блок, 6 спортисти, пораки), со истите
     domain правила. `vite build --mode demo` прави самостоен демо (hash routing, релативни патеки) за преглед.
4. **Дизајн** — „топол coaching“ (дизајн-канвас): токени во CSS променливи, светла/темна тема според системот,
   mobile-first за спортист (долна навигација), desktop-first за тренер (горна навигација). Фонтови Inter и
   Nunito се хостираат со апликацијата (без Google Fonts — GDPR).
5. **Мултијазичност** — сите текстови од `@activen/i18n` (ADR-0008). Chrome нема ICU податоци за `mk`, па i18n
   има сопствено македонско форматирање на датуми/броеви кога пребарувачот го нема (CLDR обрасци).
6. **Код-сплитинг** — тренерскиот workplace, профил и напредок се посебни chunks; спортистите не ги симнуваат.

## Последици

- - Едноставен deploy (статички фајлови), брз PWA, ист договор и правила на сервер и клиент.
- - Демото овозможува преглед и коментари без сметка и без уреди.
- − Нема SSR (не е потребен зад најава); првото вчитување зависи од JS (~155 KB gzip за спортист).
- − Google/Apple копчињата се појавуваат дури кога ќе се постават `VITE_GOOGLE_CLIENT_ID` / `VITE_APPLE_CLIENT_ID`
  и client ID-ата на серверот.
